# 金标标注规范书 v1（B 线 · 评审方 agent-b 起草）

> 对应 PRD 13 章 W1 交付物①「金标标注规范书 v1（覆盖度定义、严重度定义、版本标注规则、仲裁流程）」与 12.3 三套主评测集 + 字段级子集。
> 本规范书约束**标注产物**（data/gold/），不约束评测脚本（切片 8，A 线）——PRD 11 章纪律：「评测脚本与金标标注分离」。

## 0. 分工与独立性

| 角色 | 职责 |
| --- | --- |
| 标注人 A（实现方 agent-a / 合规岗） | 独立产出同批案件的标注（或提供系统输出作对照） |
| 标注人 B（评审方 agent-b） | 独立产出标注；本批 `eval_rev_batch1.json` 即 B 标注 |
| 仲裁人（用户 / 合规岗） | 双人分歧与口径分歧的第三方仲裁（PRD 12.3「双人独立标注 + 第三方仲裁」） |

独立性纪律：

1. 标注从**规则文本（DSL）与 PRD 语义**手工推演，不复制管线输出；
2. 与确定性管线的交叉校验（`tests/test_gold_cases.py`）是 **QA 机制**而非标注来源——分歧按第 6 节仲裁三类处置；
3. 标注人不得为让金标通过而修改实现；实现缺陷走评审意见通道。

## 1. 词表（标注产物唯一取值）

| 维度 | 取值 | 口径 |
| --- | --- | --- |
| 判定 verdict | `hit` / `miss` / `not_applicable` / `unresolved` | PRD 6.1 三态 + 未判定；`unresolved` 必带 reason_code |
| 原因码 | `NO_VERSION_MATCH` / `AMBIGUOUS_VERSION` / `MISSING_FACT` / `LOW_CONFIDENCE` / … | 绑定级用前两个；判定级用后两个起 |
| 严重度 | `重大` / `重要` / `关注` / `提示` | **只取自命中版本的规则库**（FR-AUDIT-03）；miss/unresolved 件不标严重度（null） |
| 覆盖度三类 | 已判定 / 不适用 / 未判定 | 见第 2 节 PRD 口径 |
| 引用字段 | 规则表达式实际引用的事实字段 | 与引擎 fact_refs 同口径；缺失事实的未判定件仍列引用字段 |

## 2. 覆盖度定义（PRD 口径，金标唯一口径）

```
total     = 本案考虑的全部 rule_id 数（绑定 + 绑定级须人工判定）
judged    = 绑定规则中引擎给出 hit/miss 的条数
不适用     = 绑定规则中 verdict=not_applicable 的条数
unresolved = 绑定规则中 verdict=unresolved 的条数 + 绑定级须人工判定条数
```

依据：PRD 8.4 样例与 10.2.1 线框（「未判定 2（原因码 NO_VERSION_MATCH×2）」）把**绑定级**须人工判定计入未判定。
⚠ 实现侧 `Auditor` 的 coverage 目前只计 evaluation（不含绑定级），两者存在定义差——登记于 `ARBITRATION.md` A-01，待仲裁；**金标按 PRD 口径**，仲裁改哪边由仲裁人定。

## 3. 版本标注规则

1. 适用版本按**业务发生日**取，生效区间**左闭右开** `[effective_from, effective_to)`——边界日标错是本项目最高频陷阱（切片 1 验证问题 2/3、本批仲裁 028 号同因）；
2. 唯一命中：标 `version`；不唯一或无命中：`version=null` + reason_code，**禁止猜版本、禁止填最新版**；
3. 每件案件同步记录「当时适用规则版本」清单（gold.binding 全量覆盖规则库 rule_id，不多不少）。

## 4. 事实与字段样本约定

1. `facts` = 高置信 ground truth（合成值）；缺失字段**显式**列入 `missing_facts`，不得留隐式空；
2. `eval_fact_subset=true` 的案件携带 `field_samples`，类别四选一：双路一致 / 双路不一致 / 跨渠道缺失 / 勾稽冲突——EVAL-FACT 的 120 个字段样本由各类案件的 field_samples 汇总而成（PRD 12.3：EVAL-FACT 是 EVAL-REV 的字段级子集）；
3. 双路不一致样本的 `value` 填**真值**（裁决后口径），两路取值另列 channel_a_value / channel_b_value。

## 5. 桶与配比

按 PRD 12.3 构成比例切批：EVAL-REV 200 件 = 对公信贷 50% + 小额经营贷 30% + 跨版本过渡 10% + 边界/冲突 10%。首批 30 件 = 15/9/3/3。每批必须覆盖：四个严重度档、四类原因码、左右边界日、缺事实、范围排除。

## 6. 仲裁流程

分歧三类，处置不同，全部登记 `ARBITRATION.md`（编号连续、不删改旧记录）：

| 类 | 判定 | 处置 |
| --- | --- | --- |
| G 金标笔误 | 规则文本可唯一推出正确值，金标推错 | 改金标，gold_version 补丁位 +1，留旧版 |
| S 实现缺陷 | 金标符合规则文本/PRD，管线输出不符 | 开评审意见（评审方通道），金标不动 |
| D 口径分歧 | 双方各自有据（如覆盖度定义） | 冻结现状、登记待仲裁；仲裁人裁决后若动 PRD 则记 PRD 版本行 |

批次冻结：交叉校验全绿 + 双人分歧清零（或全部登记 D 类）后，`gold_version` 去 `-draft` 冻结；冻结后修订必须升版并保留旧版（PRD 9.5「旧版仍可复现历史评测结果」）。

## 7. 不做什么

· 不编漏报率 ground truth（无外部对照集，PRD 纪律）；
· 不填 [D]-5 人工工时（合规岗实测，agent 不代填）；
· 不把外部数据集标注当金标（切片 6.5 三线之一）。

## 8. 与切片 8.0 两层协议的衔接（v1.1 增补，2026-11-28）

本规范书管**技术口径金标**（首批 30 件 = B 侧技术层独立全口径标注，已与管线交叉校验）；
`docs/GOLD_LABELING.md` 管**判断性盲标**（五字段）。两层互补不冲突。
对齐审查发现三个协议缺陷，登记于 `ARBITRATION.md` B1-003/004/005：

- **P-1 分工自相矛盾**：GOLD_LABELING §2「A 组奇数 / B 组偶数」是**拆分标注**，
  与其 §5 仲裁规则、`compare_gold.py` 的交集一致率语义、PRD 12.3「双人独立标注」
  （每件双标）全部冲突——拆分口径下案件级一致率恒为空集。**应改为双方全量标注**，
  奇偶只可作起草顺序。修订落地前 B 侧不按拆分口径开标。
- **P-2 盲性靠自觉**：`truth.jsonl` 入库在共享仓库，任何有仓库权限的裁判都能 peek。
  缓解：B 侧开标前在**自己的工作树删除 `pack-*/truth.jsonl`** 并在标注文件头声明；
  比对与仲裁由仲裁人侧执行。
- **P-3 污染披露（已裁决 ①）**：评审方在协议审计中读过 A 侧试点 5 条标注
  （FG-B-0001…0005）。仲裁人裁决：换新前缀 **FG-C** 重生成试点 5 件替换之，
  原 5 行标注作废保留；执行规格见 `ARBITRATION.md` B1-005。

**B 侧开标条件**：P-1 修订 + P-2 缓解就位 + P-3 裁决；范围 pack-b 全量 30 件（或按 P-3 裁决）。
