### 关键设计点（建议重点看这 5 处）

1. **金标分两层，只有一层需要人** —— 技术性真值（事实、命中、版本、覆盖度、原因码）由**生成器直接产出**（合成数据是按规则生成的，生成参数就是真值）；判断性标注（识读、理由、严重度恰当性、处置档位、误报）才由 Agent 标。**技术性部分不用 Agent**——用不确定手段确定已知的事是纯浪费。
2. **盲标的前提是"裁判没见过答案"** —— 实现方在调试生成器时**必然**见过早期批次的真值。所以盲标必须用**全新批次**（`--seed 20261201 --prefix FG-B`），manifest 记 `blind_batch`。这条是方法论上最重要的一条：开发者天然见过自己系统的输出，让他标自己系统的金标，盲性就破了。
3. **任务包与真值物理分离** —— `materials.jsonl` 只有材料、待标字段与**规则清单**（规则对所有审查岗可读，给它不泄漏判定结果）；`truth.jsonl` 只给系统比对用。裁判能知道有哪些规则，但不能知道"本案判成了什么"。
4. **枚举封闭** —— 五个字段的取值必须落在 `LABEL_SCALES` 内。自由文本无法机械比对，一致率统计就退化成人工阅读。
5. **分歧不是失败，是信号** —— 两个 Agent 分歧的字段**进仲裁清单**并给仲裁提示（规则适用性以技术真值为准、严重度以规则库为准）；分歧率本身进评测报告，它是"标注规范是否够清楚"的度量。

### 关键设计点（建议重点看这 5 处）

1. **回放引擎零改动** —— `SqliteEventLog` 与切片 6 的 `EventLog` 暴露**同样的方法**（`append` / `events` / `since` / `verify`），回放引擎直接吃它，**切片 6 的回放逻辑一行没改**。这是当初把接口收窄到鸭子类型的回报。
2. **跨进程哈希链可校验** —— 换一个 `Repository` 实例（模拟另一个进程）打开同一个库，链仍能整链重算通过；把某条事件的 payload 在库里改掉，`verify()` 立刻失败并定位到那一条。只追加的保证因此**从内存搬到了文件**。
3. **契约先行、框架可替换** —— `api/contracts.py` 只声明"有哪些端点、返回什么字段"，**零 Web 框架依赖**；本地用标准库 `http.server` 起（零安装），切片 9.1 换 FastAPI / uvicorn 时**契约一行不改**。
4. **响应形状不许悄悄漂移** —— 每个端点的必填字段被契约声明，响应缺字段直接报错。接口演化的代价因此从"上线后才发现前端炸了"变成"测试就红"。
5. **本切片不做写端点** —— PRD 9.4 权限三原则第 2 条「只读优先：Agent 与系统集成账号一律只读业务数据」。写端点必须与鉴权一起上（切片 9.1），单独开写接口等于把审计对象留在体系外。
